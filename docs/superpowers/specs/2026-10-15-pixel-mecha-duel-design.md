# 像素机甲对战 · PIXEL MECHA DUEL —— 设计文档

- 日期：2026-10-15
- 交付物：`/workspace/pixel-mecha-duel.html`（单文件、零依赖、双击即玩）
- 技术形态：HTML5 Canvas 2D，逻辑分辨率 320×180，固定 60FPS 步长，CSS 整数倍放大
- 素材形态：100% 程序化生成（像素矩形 + 程序合成音效），无任何外部图片/音频文件

---

## 1. 玩法设计

### 1.1 形式与目标

2D 侧视 1v1 竞技场对战。单局把对手 HP 打到 0 即胜出；先赢 2 局者（三局两胜 BO3）赢下整场。

### 1.2 操作

战斗操作：

| 动作 | P1 | P2 |
| --- | --- | --- |
| 移动 | `A` / `D` | `←` / `→` |
| 跳跃 | `W` | `↑` |
| 防御 | `S` | `↓` |
| 近战 | `F` | `K` |
| 远程炮 | `G` | `L` |
| 冲刺 | `Shift` | `/` |

界面与系统操作：

| 场景 | 按键 | 作用 |
| --- | --- | --- |
| 标题设置界面 | `↑` / `↓`（或 `W` / `S`） | 移动光标；自动跳过当前不可用的行，按住约 18 帧后每 5 帧连翻 |
| 标题设置界面 | `←` / `→`（或 `A` / `D`） | 切换当前行取值，左右任意方向都翻转，无"端点按不动" |
| 标题设置界面 | `Enter` / `Space` | 以当前设置开始对局 |
| 标题设置界面 | `1` / `2` | 快速开局：单人打 AI / 双人同屏 |
| 对局中 | `Esc` | 打开暂停菜单（冻结战斗与计时） |
| 暂停菜单 | `↑↓` 选择 · `←→` 改值 · `Enter` 确认 · `Esc` 直接继续 | 同标题界面三行 + `RESUME` / `QUIT TO TITLE` |
| 任意时刻 | `M` / `T` | 快捷静音 / 切换 AI 难度 |
| 结算画面 | `Enter` 重打一局 · `Esc` 回标题 | |

### 1.3 数值表

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| HP | 100 | 归零即 KO |
| 能量 | 0–100 | 自动回充 0.14/帧（≈8.4/秒），从 45 起步 |
| 单局时限 | 60 秒 | 到时按剩余 HP 高者胜；同血为平局 |
| 近战 | 伤害 8，射程 22px | 判定帧 5–10/共 18 帧，冷却 16 帧，命中回充 6 能量 |
| 远程炮 | 伤害 12，消耗 30 能量 | 第 9 帧发射，共 26 帧，冷却 22 帧，弹速 4.2 |
| 冲刺 | 消耗 20 能量 | 14 帧，速度 4.3，全程无敌帧，冷却 26 帧 |
| 防御 | 减伤 70%（伤害取 30%） | 消耗 0.5/帧（≈30/秒），仅对正面有效，击退降到 35% |
| 受击硬直 | 13 帧 | 期间不可操作，带少量击退与浮空 |
| 角色碰撞盒 | 12×24 px | 机甲精灵同为 24px 高，脚底对齐 |

### 1.4 胜负与回合流程

```
title ──(1 / 2 / Enter)──> countdown(3·2·1·FIGHT!) ──> fight
                                                       │
                     ┌─────────────────────────────────┤
                     │ HP 归零 → KO                     │ 60 秒倒计时归零
                     ▼                                 ▼
                  roundover(140 帧结算画面) <───── 血量高者胜 / 平局
                     │
        ┌────────────┴────────────┐
        │ 任一方已 2 胜            │ 否则
        ▼                         ▼
   matchover(结算 + 重开)      startRound(下一局)
```

- 时间到判负时，败者进入受击姿态，避免"站着输"的观感断裂。
- KO 触发强顿帧（14 帧）+ 强震动（10），并爆发白色/机体双色粒子。
- 对局中按 `Esc` 进入暂停：`G.paused` 为真时**冻结角色、弹丸与计时**，`step()` 只处理暂停菜单输入并推进粒子衰减；`Esc` 或 `RESUME` 继续，`QUIT TO TITLE` 直接回标题（并复位光标与设置显示）。

### 1.5 设置界面

标题界面即为设置面板，三行设置项：

| 行 | 取值 | 说明 |
| --- | --- | --- |
| MODE | `SOLO VS CPU` / `2P LOCAL` | 决定 `P2` 由 AI 接管还是键盘接管 |
| CPU LEVEL | `EASY` / `NORMAL` | 仅在 MODE 为 `SOLO VS CPU` 时生效；2P 模式下该行置灰并显示 `--` |
| SOUND | `ON` / `OFF` | 关闭后 `sfx()` 直接返回，不再合成任何音效 |

对局中 `Esc` 打开的暂停菜单复用同一套渲染与切换逻辑，多出 `RESUME` 与 `QUIT TO TITLE` 两行（共 4 行）。

三个设置项都是二选一，因此 `←` / `→` 任意方向都直接翻转取值，杜绝"在端点按了没反应"；纵向移动用 `stepRow()` 环绕查找，自动跳过置灰行，让光标永远不会停在按不动的死行上。

### 1.6 手感设计（让"简单 Demo"也有打击感）

| 机制 | 实现 |
| --- | --- |
| 顿帧 hitstop | 命中冻结全局逻辑 7 帧（防御 3 帧、KO 14 帧），仅推进粒子与震动 |
| 屏幕震动 | 命中 5 / 防御 2 / KO 10，逐帧 ×0.88 衰减 |
| 受击反馈 | 机体闪白 7 帧 + 反向击退 + 轻微浮空 + 双色粒子爆发 |
| 冲刺残影 | 沿冲刺反方向绘制 2 层低透明度机甲 |
| 无敌帧提示 | 冲刺期间叠加半透明替身叠加层 |
| 能量满提示 | 能量条在 >96% 时变为亮黄绿，提示"可连发大招" |

### 1.6 AI 设计

AI 只在 `idle/walk/jump` 状态决策，每 12 帧（NORMAL）/ 26–40 帧（EASY）重新决策一次，依据"距离 + 能量 + 自身血量"在 6 种行为中选一个：

| 行为 | 触发条件 |
| --- | --- |
| `approach` | 距离 30–82px 且随机数落在接近分支 |
| `melee` | 距离 < 30px（NORMAL 概率 62%），未冷却时出拳，否则继续贴近 |
| `cannon` | 距离 > 38px 且能量 ≥ 30，倾向在远距离消耗 |
| `block` | 近距离或血量 < 28 时按概率防御 |
| `back` | 近距离小概率后撤拉开距离 |
| `hop` | 侦测到对手开炮时跳跃躲避 |

EASY 档额外做两件事：决策间隔拉长、约 30% 概率放弃出招。NORMAL 档在距离 > 62px 时有 2% 概率起跳接近。

## 2. 核心代码结构

单文件内按"职责分层"组织，共 11 段（`pixel-mecha-duel.html` 内注释分区对应）：

| # | 分层 | 职责 | 关键实现 |
| --- | --- | --- | --- |
| 1 | 全局配置 | `CFG` 集中所有可调数值 | 见 §1.3 数值表；调平衡只改这里 |
| 2 | 像素字体 | `FONT` / `GLYPH` / `drawText*` | 3×5 位图字体，画布内所有英文文字统一走它，保证复古像素感 |
| 3 | 场景素材 | 星空、山脊、落日 | 固定随机种子 `seed` 生成，保证每次运行画面一致 |
| 4 | 音效 | `tone()` / `sfx()` | WebAudio 振荡器程序合成 12 种音效，首次按键时解锁 AudioContext |
| 5 | 输入系统 | `keys` / `justDown` / `readInput()` | 双人各一套键位映射表；`justDown` 集合实现"同帧刚按下"边缘判定 |
| 6 | 战斗机 | `Fighter` 类 | 单类承载状态机 + 物理 + 攻击判定；`update(inp, foe)` 是唯一入口 |
| 7 | 战斗判定 | `attackBox` / `meleeHit` / `applyHit` | 伤害/防御/击退/顿帧/震动/KO 统一在 `applyHit` 收口 |
| 8 | 弹丸与粒子 | `shots` / `particles` / `burst` | 双边弹丸对撞同归于尽；粒子受重力衰减 |
| 9 | AI | `aiInput(me, foe)` | 输出与真人完全相同的 `inp` 结构，战斗机不区分谁在操作 |
| 10 | 回合流程 | `G` 状态机 / `startMatch` / `startRound` / `endRound` / `separate` | `G.phase` 五态驱动整个游戏；`separate` 做双方软推挤防重叠 |
| 11 | 渲染 | `drawStage` / `drawMecha` / `drawHUD` / `drawBanner` / `render` | 先场景 → 平台 → 影子 → 角色（按 x 排序定前后）→ 弹丸 → 粒子；HUD 在震动坐标系外绘制 |

### 2.1 关键数据流

```
浏览器 keydown/keyup ──> keys{} / justDown{}
                            │
        ┌───────────────────┴────────────────────┐
        │ 人类玩家                               │ CPU
   readInput(CTRL.pN, jd)                   aiInput(P2, P1)
        └───────────────────┬────────────────────┘
                            ▼  统一为 inp 结构
                   Fighter.update(inp, foe)
              ┌─────────────┴──────────────┐
              │ 状态机 → meleeHit/fireShot │ 物理积分 → 地面/平台吸附
              └─────────────┬──────────────┘
                            ▼
                     applyHit(伤害/防御/KO) ──> G.koLoser
                            ▼
              G.phase 状态机（fight → roundover → matchover）
                            ▼
                          render()
```

### 2.2 设计上刻意的解耦

- **人类与 AI 同构**：AI 只是"另一个输入源"，`Fighter` 完全不感知对手是谁，因此加网络对战或回放只需替换输入源。
- **数值与逻辑分离**：所有平衡参数在 `CFG`，无散落魔法数字。
- **判定与表现分离**：`applyHit` 只负责数值与状态，粒子/震动/音效作为它的副作用集中在此处调用，替换表现层不影响判定。
- **固定步长**：`frame()` 用累加器以 `FRAME_MS` 推进 `step()`，渲染与逻辑解耦，物理与计时不受帧率影响（最多单帧补 5 步）。

## 3. 基础素材方案

全部素材在运行时由代码生成，仓库里没有任何图片/音频资源。

### 3.1 机甲精灵（程序化像素矩形）

以"脚底中心"为原点建模，向上为负 y，`+x` 为面朝方向；绘制前 `ctx.scale(facing, 1)` 完成朝向翻转，因此**同一套绘制代码同时产出红/蓝机甲**（红 `#e2453a` / 蓝 `#3f86e8` 两套调色板）。

```
        头部  6×6     ← 面罩发光 3×2，天线 1×3
      前肩甲  4×4
   躯干 8×9          ← 背侧阴影 2×9、高光带 8×1、能量核心 2×3 + 1×1 白点
   前臂 3×9 + 手 3×3  ← 攻击时前伸，延伸出 9px 发光刃（含 1px 白色刃边）
   前腿 3×8 + 脚 5×1
   后肢/后臂（暗色，先绘制，形成层次）
```

### 3.2 角色动画（状态驱动的肢体偏移，共 8 态）

| 状态 | 动画手法 |
| --- | --- |
| `idle` | 整体正弦上下浮动 1px |
| `walk` | 前后腿反相 ±2px，手臂反相 ±1.5px，身体随步频微沉 |
| `jump` | 前腿收 -3px、后腿伸 2px，双臂上抬 -3px |
| `attack` | 5 帧内前臂前伸至 9px、身体前倾 2px（配合发光能量刃） |
| `shoot` | 前倾 1px，肩上炮管 8×3 + 炮口 4×2 + 2×2 白色亮点 |
| `block` | 重心下沉 2px，身前竖立 3×17 半透明能量护盾（上下 1px 白边） |
| `dash` | 前倾 3px，前后腿拉开，另绘 2 层残影 |
| `hurt` / `ko` | 后仰（KO 6px）+ 头部转暗，叠加强制白闪 |

闪白用"调色板整体替换为白色"实现（`R()` 绘制辅助函数内判 `white`），不需要第二套精灵图。

### 3.3 场景与特效

| 素材 | 生成方式 |
| --- | --- |
| 天空渐变 | 4 段 stops：`#180f33 → #3a2352 → #7a3a55 → #c96a4a`（黄昏紫→橙） |
| 星空 | 52 颗星，随机三档亮度（白 / `#9d94d6` / `#6d64a8`） |
| 像素落日 | 半径 13 的圆按行宽公式逐行填充，再叠 4 条扫描暗线 + 用天空渐变"挖空"4 条横切条（复古落日） |
| 远景山脊 | 两层：固定种子随机游走折线（80–110px）+ 双正弦波叠加的近景剪影 |
| 地面 | 深色地板 `#120c22` + 顶面 1px 亮线 + 16px 竖网格 / 6px 横网格（赛博感） |
| 平台 | 2 座单向平台（26–84px、236–294px，y=116），顶面亮线 + 8px 交错暗块 |
| 影子 | 按"下方最近可站立面"计算落点与压缩量，随离地高度变淡变窄 |
| 弹丸 | 10×2 拖尾（白 22% 透明）+ 8×8 机体光色方块 + 4×4 白色内核 |
| 粒子 | 命中爆发，受重力 0.14/帧、水平阻尼 0.98，按剩余寿命线性淡出 |
| 音效 | 11 种 `sfx` 事件：挥拳(820→320Hz)、命中(190Hz+95Hz 双层)、防御(1350Hz)、炮击(430→120Hz)、冲刺、跳跃、KO(170→40Hz)、FIGHT、单局获胜(双音)、整场获胜(四音琶音)、UI |

### 3.4 画布内文字

`FONT` 用可读的 `['. # .', '# . #', ...]` 字符串定义，启动时压成 3×5 位图。支持 A–Z、0–9 与 `: . - / + ! < > = %`。字宽 3px、字距 1px，缩放整数倍（标题 3×、倒计时 "3/2/1" 4× 与 "FIGHT!" 3×、HUD 时间 3×）。中文说明放在画布外的 HTML 提示条中，避免像素字体无法渲染中文。

## 5. 后续可扩展方向

1. 增加"上挑/下劈"等额外出招与连招计数，向小型格斗游戏靠拢。
2. 必杀技系统：能量满时开出招消耗全部能量，附特写顿帧。
3. 把 `readInput` 换成网络输入流即可支持联机；把输入换成录制回放即可做重放功能。
4. 场景选择（不同配色天空 / 多平台地形）。
